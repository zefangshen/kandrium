# AGENTS.md

Guidance for AI coding agents working in this repository. Read before making
changes. User-facing overview lives in [README.md](README.md).

## What this is

Kandrium is a local-first Kanban app on a pure-Rust stack:

- **eframe/egui 0.36** desktop UI (`crates/app`, binary `kandrium-app`)
- **rmcp 3.5** stdio MCP server (`crates/mcp`, binary `kandrium-mcp`)
- **rusqlite 0.40** (bundled SQLite) shared data layer (`crates/core`, crate `kandrium-core`)
- **cargo-packager** for macOS `.app`/`.dmg` bundling

Workspace, edition 2024. All comments, identifiers, and docs are in English.

## Architecture rules

- `kandrium-core` is the single source of truth for schema, models, and data
  operations. All service functions are synchronous and take
  `&rusqlite::Connection`. The app and the MCP server must stay consistent:
  do not implement data logic in a front-end crate — add it to `core` and
  expose it from `lib.rs`.
- The DB is SQLite WAL + `foreign_keys=ON` + 5 s busy timeout, so the app and
  MCP server processes share one file. The app detects external commits with a
  background thread polling `PRAGMA data_version` (`crates/app/src/watcher.rs`).
- Async work reaches the egui UI thread through tokio/`std::sync::mpsc`
  channels; never touch UI state from another thread.
- The MCP wire format follows the legacy TypeScript conventions: camelCase
  JSON (`#[serde(rename_all = "camelCase")]`), pretty-printed text results,
  tool-level `isError` on failure. The server exposes a curated 13-tool
  subset: column create/rename/delete/move are intentionally app-only, while
  `archive_all_cards` remains. Preserve the names and schemas of the exposed
  tools — MCP clients may depend on them.
- The SQL schema (`crates/core/src/schema.sql`, v1, applied by
  `db::run_schema` through `rusqlite_migration` via `PRAGMA user_version`) is
  identical in shape to the legacy Drizzle schema so the row-copy importer
  works. Keep both compatible; new schema steps must be idempotent
  `CREATE TABLE IF NOT EXISTS` / additive migrations. Additive steps go in a
  separate file (`schema_v2.sql`, `schema_v3.sql`, `schema_v4.sql`, registered
  in `db::migrations` in order) so earlier files stay byte-identical. v3 adds
  project identifiers and card ↔ project columns atomically (DDL + backfill +
  version bump in one transaction); v4 lowercases existing identifiers
  (data-only, same NOCASE unique index).
- Projects (`crates/core/src/projects.rs`) own a board each. Those boards are
  hidden from the Tasks tabs (`list_boards`) with
  `NOT IN (SELECT board_id FROM projects)`; the header re-adds the currently
  open project board as a tab via its "active board not in the tab list" rule.
  The Projects view is `crates/app/src/views/projects.rs`.
- Every project has a short identifier (1–10 lowercase chars, `a–z 0–9 - _`,
  unique case-insensitively). It is derived from the name on create and
  regenerated by renames until the user edits it on the Overview page
  (`identifier_locked`). The tree labels projects with the identifier (full
  name in the tooltip) and the filter matches both.
- Cards carry a nullable `project_id`. Cards created on a project board inherit
  that project; cards on normal boards can be tagged with one (Project picker
  in the card modal). Project cards use the modal's "Show on Tasks boards"
  checkbox + board picker; "Move to board" is hidden for them.
  `area_board_id` files a project card onto one normal board
  (Career / Work / Life / any non-project board): `get_board` appends
  those cards to the matching status column in `Column.mirrored` (they stay in
  their real project column in SQLite). Area-filed project cards also appear
  on the All board, labelled with the area board's title (not the hidden
  project board); mirrored cards are clickable but **not draggable** and are
  not drop anchors. Use `set_card_project` / `set_card_area` for these links.
  `get_board` resolves `project_identifier` and the per-board `meta_label`:
  a project board shows the filed area's title in the card's second row
  (nothing when unfiled), while normal/area boards show the project
  identifier. `meta_label` is UI-only (serde-skipped).
- The project detail pane is tabbed: pinned Overview and Tasks tabs (neither is
  closable) and one closable tab per open markdown/text document.
  `projects::show_tree` draws the
  left panel, `projects::detail_tab_strip` returns the active `DetailKind`, and
  the app draws Tasks itself (it reuses the normal `content_board` pipeline —
  the board in `self.board` is chosen by `displayed_board_id`, which is the
  project's board while the Tasks tab is open). The Overview/Doc bodies stay in
  `projects::detail_body`; the Overview title renames inline on double-click
  (`title_field`: Enter/blur commits, Esc cancels). Renames regenerate the
  identifier until it is locked and sync the project board title.
  Project documents are read/written through
  `projects::read_doc` / `write_doc` (root-guarded, `<projects_root>/<id>/`),
  and the shared markdown editor/preview is `widgets/markdown.rs`.
- IDs are 24 lowercase hex chars (`db::uid()`), matching the old app. Seed data
  uses fixed string ids (`board_career`, `col_work_todo`, ...).

## Naming constraints (do not regress)

Product is **Kandrium** (renamed from Planly). Crates/binaries are
`kandrium-core` / `kandrium-app` / `kandrium-mcp` / `kandrium-import`, bundle
id `app.kandrium.desktop`, window title "Kandrium". The only intentional
remaining `planly` strings are the **legacy database paths**
(`planly-rs/planly.db` for auto-migration, `planly/planly.db` for the Electron
importer) and historical reference comments.

## Commands

```sh
cargo run -p kandrium-app          # desktop app (also: just run)
cargo run -p kandrium-mcp          # MCP stdio server
cargo test --workspace             # ~40 tests, must stay green
cargo clippy --workspace           # must be warning-free
cargo fmt
cargo packager --release           # build Kandrium.app + DMG (packager.json)
```

Before finishing a change: run `cargo fmt`, `cargo clippy --workspace`, and
`cargo test --workspace`. All three are expected to pass cleanly.

### macOS sandbox note for agent shells

A GUI launched from a sandboxed agent shell can read the default DB but every
SQLite write fails with `SQLITE_READONLY` (`~/Library/Application Support` is
not writable by the sandboxed process). `dangerouslyDisableSandbox` does not
bypass this. Launch through the dev bundle wrapper instead:

```sh
open -n target/Kandrium-dev.app
```

`target/Kandrium-dev.app` is a minimal `.app` bundle whose executable is a
symlink to `target/debug/kandrium-app`, so every rebuild is picked up on the
next launch. LaunchServices starts it as a real bundle app, fully outside the
agent sandbox (DB writes work) and with no Terminal window hosting it —
`open -n` on the bare binary re-parents under Terminal.app, and closing that
window kills the app. Restart after a rebuild with
`killall kandrium-app; open -n target/Kandrium-dev.app`. The bundle lives in
the cleanable `target/`; if missing, recreate it: `Contents/MacOS/kandrium-app`
as a symlink to `../../../debug/kandrium-app`, a `Contents/Resources/icon.icns`
copied from `crates/app/packaging/icon.icns`, and a bare `Contents/Info.plist`
(APPL, bundle id `app.kandrium.desktop.dev`, `CFBundleExecutable`
`kandrium-app`, `CFBundleIconFile` `icon.icns`). Without the icon resource and
key, LaunchServices shows the generic application icon in the Dock.

For testing with a writable database, set `KANDRIUM_DB` to a path under the
workspace or `/tmp`. Visual verification may be impossible from the agent
shell (screen capture blocked) — ask the user to confirm UI changes.

## egui conventions (hard-won — read before touching UI code)

- **Fonts**: all font sizes live ONLY in the `text_styles` table in
  `theme.rs::apply_visuals` (Small 13 / Body 16 / Button 16 / Heading 20 /
  Monospace 16, plus named `strong` and `small-strong`). Widgets pick a
  `TextStyle` and resolve it with `theme::font_id(ui, style)` for painter text.
  Never introduce a separate scaling layer or pass explicit pixel sizes.
- **Icons**: inline Lucide SVGs via `crates/app/src/icons.rs`. Do not re-add
  `egui-phosphor`.
- **Tables**: use `egui_extras::TableBuilder` (fixed columns, sticky header,
  striped rows) — see `crates/app/src/views/archive.rs`. Archived page board
  filter default must be `"all"`, never `""`.
- **Drag-and-drop**: hand-rolled (`dnd.rs` + `anim.rs`), no community crate.
  Easing constants: `cubic-bezier(0.20, 0, 0, 1)` for reflow/lift and
  `cubic-bezier(0.40, 0, 0.20, 1)` for snap-back. Tune timing only in
  `anim.rs`.
- **Scrollbars are floating and reserve zero global layout space**
  (`ScrollStyle` in `theme.rs`). Content that must not sit under a bar gets the
  scoped constant gutter: `widgets::CONTENT_RIGHT_INSET` (7 px) via
  `.content_margin(...)` inside card-list ScrollAreas or `widgets::right_inset()`
  for direct layout. Set `scroll.floating_allocated_width` only locally for
  contexts needing a reserved lane, and reset it at the top of a content
  closure that spawns nested scroll areas.
- **Nested scroll inside horizontal scroll**: `ScrollArea::horizontal` gives
  infinite available width, which collapses nested vertical scrolls to glyph
  width. Allocate columns with
  `ui.allocate_ui_with_layout(vec2(280.0, h), Layout::top_down(Align::LEFT), ...)`.
  Never call `set_min_width/set_max_width` on a horizontal row placer. Capture
  the height ceiling BEFORE entering `ui.horizontal_top(...)`, floor empty
  drop-zone bodies at ~30 px, and allocate the 280 px width unconditionally.
- **Frames shrink-wrap content**: call `ui.set_min_width(ui.available_width())`
  first inside a frame closure on a vertical placer.
- **Loop-generated widgets need explicit IDs**: wrap per-entity content in
  `ui.push_id(("prefix", entity.id.as_str()), |ui| ...)` to avoid duplicate
  `ScrollArea`/widget ID clashes.
- **Fixed-height multiline editor**: outer fixed bordered `Frame` +
  inner `ScrollArea::vertical().max_height(h).auto_shrink([false; 2])` +
  frameless `TextEdit::multiline` (egui 0.36 multiline has no internal scroll).
  Reference: `description_editor()` in `widgets/card_modal.rs`.
- **egui context lock is not reentrant**: never call `ctx.input()` inside
  `ctx.data_mut()`; read input first.
- eframe's app-creator closure runs before `applicationDidFinishLaunching`;
  do "once the app is running" work (e.g. dock icon) on the first frame in
  `app.rs::logic()` with `ctx.request_repaint()` retries.

- **Tree panels collapse to a rail**: Projects, Notes and Documents share
  `widgets::collapse_button` (chevron in the panel header),
  `widgets::expand_button` and `widgets::RAIL_W` (30 px). The expanded panel
  keeps its own id so the dragged width survives a collapse/expand cycle; the
  rail uses a separate `<page>-tree-rail` id so it never overwrites it. The
  `tree_open` flag on each view state is persisted per section in `SavedState`.

- **Documents** (`views/documents.rs`, core `documents.rs`) list PDFs and
  Markdown under `<data_dir>/kandrium/documents/` (`KANDRIUM_DOCS`). PDF tabs
  use the worker reader and JSON annotation sidecars; Markdown tabs reuse
  `widgets::markdown` with debounced autosave, like Notes. The tree header's
  upload button opens a native `rfd` multi-select and copies files into the
  selected folder (unique `-2` names, no sidecars). Open tabs persist as
  root-relative paths; Markdown editor mode is per tab, not persisted.

## Headless UI tests

Geometry/widget logic can be tested without a GPU with
`egui::Context::default()` + `ctx.run_ui(RawInput::default(), ...)`. In every
headless test module call `theme::install_fonts(&ctx)` and
`theme::apply_visuals(&ctx, false)` first, and clear
`output.textures_delta` before the context drops (avoids a drop panic). Scan
`FullOutput.shapes` for `"use of"` text to catch duplicate-ID warnings.

## Design system

Neutral gray-on-gray PdfCraft style: single blue accent, Inter typography,
6 px corner radius, transparent hover/press wash with 1 px content offset on
press, floating scrollbars, Lucide icons, bottom-center inverted toasts,
reduced-motion support.

## Database location / env vars

- `KANDRIUM_DB` overrides the DB path; default `<data_dir>/kandrium/kandrium.db`.
- `KANDRIUM_OLD_DB` overrides the legacy Electron source for `kandrium-import`.
- `KANDRIUM_NOTES` overrides the notes root; default
  `<data_dir>/kandrium/notes/` (plain `.md` files, no DB involvement).
- `KANDRIUM_DOCS` overrides the documents root; default
  `<data_dir>/kandrium/documents/` (PDFs + Markdown; PDF annotations live in
  `*.pdf.kandrium.json` sidecars).
- `KANDRIUM_PROJECTS` overrides the projects root; default
  `<data_dir>/kandrium/projects/` (one folder of plain files per project —
  the folder/project tree itself lives in SQLite, schema v2).
- Auto-migration from `<data_dir>/planly-rs/planly.db` runs once at app and MCP
  boot (staged `VACUUM INTO`, never writes the source). A `KANDRIUM_DB`
  override opts out of auto-migration.
